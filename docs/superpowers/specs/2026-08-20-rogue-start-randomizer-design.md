# 黑流树海开局随机器 — 设计文档

- 日期：2026-08-20
- 状态：已与用户确认

## 1. 目标

做一个明日方舟集成战略「沉沦者的黑流树海」（本期肉鸽主题）的开局随机器：随机选择开局分队和开局招募组合，可选地按招募组合中每个券位的职业范围随机出具体干员。形态是一个无需后端的网页。

## 2. 范围

### 做

- 随机**分队**（从本期主题的全部分队中均匀随机）
- 随机**招募组合**（从本期主题的全部初始招募组合中均匀随机）
- 「随机具体干员」开关：开启后，按组合中每个券位允许的职业范围，从对应职业干员池中随机一个具体干员
- 干员池过滤：按稀有度筛选（勾选参与随机的星级）、手动排除指定干员
- 单项重摇：分队、每个券位都可单独重新随机，互不影响
- 设置项（开关、稀有度、排除名单）持久化到浏览器 localStorage

### 不做（本版明确排除）

- 任何图片素材（头像、图标）：全部用文字展示
- 按用户自有干员（box）过滤
- 历代主题的实际数据（仅数据结构上预留多主题扩展）
- 后端服务、账号系统、结果分享
- 游戏内进阶机制（助战招募、临时招募规则细节不做特殊处理）

## 3. 整体架构

**离线数据提取 + 纯静态前端**（方案 A）：

1. 用户浅克隆 ArknightsGameResource 仓库到本地（脚本通过配置项或命令行参数指定路径）
2. 运行 Node.js 提取脚本，从游戏数据中读出本期主题的分队、招募组合和全部干员数据，输出一份精简 JSON 到前端源码目录
3. Vue 3 静态单页应用打包该 JSON，构建产物为纯静态文件

游戏更新后重跑提取脚本即可更新数据。

## 4. 数据模型（生成的 JSON）

按主题组织，预留多主题扩展：

```jsonc
{
  "generatedAt": "2026-08-20",
  "themes": [
    {
      "id": "rogue_5",              // 以游戏数据中的实际主题 id 为准
      "name": "沉沦者的黑流树海",
      "squads": [
        { "id": "...", "name": "...", "desc": "..." }
      ],
      "recruitGroups": [
        {
          "id": "...",
          "name": "...",
          "slots": [
            { "classes": ["PIONEER", "WARRIOR"] }  // 该券位允许的职业
          ]
        }
      ]
    }
  ],
  "operators": [
    { "id": "char_xxx", "name": "...", "profession": "WARRIOR", "rarity": 6 }
  ]
}
```

说明：

- 分队/招募组合的具体字段名以实际游戏数据为准，实现提取脚本时核对
- 干员列表只保留可被招募的干员（按游戏数据中的可招募标记过滤）
- 职业使用游戏内职业枚举（先锋/近卫/重装/狙击/术师/医疗/辅助/特种），展示时映射为中文

## 5. 数据提取脚本

- 位置：`scripts/extract.mjs`（Node.js，无第三方依赖，只读 JSON 文件）
- 输入：ArknightsGameResource 仓库本地路径
- 处理：读取游戏数据文件 → 提取黑流树海主题的分队/招募组合 + 可招募干员（名称、职业、稀有度）→ 写 `src/data/rogue-data.json`
- 自检：输出前校验分队、招募组合、干员数量均大于 0 且字段齐全；跑完打印摘要（各主题分队数、组合数、干员总数）

## 6. 前端

- 技术栈：Vue 3 + Vite + TypeScript，无路由、无状态库（一个组合式函数管状态即可）
- 布局：单栏垂直流
  - 顶部：标题
  - 设置区（默认折叠）：「随机具体干员」开关、稀有度勾选（3/4/5/6 星）、排除名单管理（按名字搜索干员加入/移除）
  - 中间：大号「开始随机」按钮
  - 结果区：分队卡（名称 + 效果描述）→ 招募组合（名称 + 券位列表；每个券位显示职业范围，开关开启时显示随机到的干员名和星级）；分队和每个券位各带一个小「重摇」按钮
- 随机逻辑：
  - 分队、招募组合在各自集合内均匀随机
  - 券位随机干员：候选 = 干员池中满足「职业在该券位允许范围内 ∧ 稀有度被勾选 ∧ 不在排除名单」的干员，均匀随机
  - 单项重摇只重抽对应项，其余结果不变
- 设置持久化：localStorage；读取时校验，非法值回退默认

### 组件划分

- `App.vue`：页面组装与状态
- `SettingsPanel.vue`：折叠设置区（开关、稀有度、排除名单管理）
- `RollButton.vue`：开始随机按钮
- `SquadCard.vue`：分队结果卡（含重摇）
- `RecruitSlots.vue`：招募组合 + 券位列表（含每券位重摇）
- 纯逻辑独立成 `src/lib/roll.ts`（池过滤、随机抽取），与 UI 解耦以便单测

## 7. 错误处理

- 数据 JSON 缺失或格式非法：页面显示明确错误提示，不白屏
- 过滤后某券位候选池为空：该券位显示「池子已空，请放宽筛选」，其余结果正常展示
- 排除名单中包含数据更新后不存在的干员 id：加载设置时自动剔除并提示一次

## 8. 测试

- Vitest 单元测试覆盖 `src/lib/roll.ts`：池过滤（职业/稀有度/排除）、券位职业约束、单项重摇不影响其他项、空池行为
- 提取脚本自检（见第 5 节）

## 9. 构建与部署

- 本地开发：`npm run dev`
- 构建产物为纯静态文件；部署到 GitHub Pages 留作后续可选项，本版不强制
