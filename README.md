## 项目简介

RollLike（中文名：随机工具）用于决定集成战略的开局。进入“随机开局”时，先在弹窗中选择并确认一种开局方式。“随心所欲开局”对应游戏中的“随心所欲”：玩家按实际随机获得的三张招募券填写职业，工具为每张券随机提供三名六星，再由玩家从本轮结果中确认一名开局干员，其余干员自行搭配。分队可以手动选择或独立随机。

“全随机开局”可以直接随机分队、招募组合和全部开局干员，结合初始希望、分队减免和干员自身减免，为每张券随机一名当前预算能够招募的干员。

项目是纯静态网页，不需要登录，不连接游戏客户端，也没有后端服务。游戏数据和图片资源在构建时打包，浏览器只负责随机计算和保存本地设置。

## 功能亮点

- **随心所欲开局**：按游戏实际给出的三张券填写职业，重复职业可以多次填写，最多提供九名不重复的六星干员，选中并确认一名开局干员；可选干员不足时展示实际人数和缺额。
- **开局方式固定**：在弹窗中确认方式后，仅显示该方式的功能；通过“重置开局”重新选择，确认重置后清空开局草稿。取消弹窗保留当前开局。
- **随机抽取干员**：无需先随机或确认开局，支持单职业、双职业、地面／高台和任意招募券，抽取干员后由玩家确认一名；不输入或筛选希望。
- **招募记录**：确认开局或局内招募后自动记录干员，已招募者不再参与后续干员抽取；六星展示在“已选干员”中。
- **已选干员**：集中展示已确认、手动添加及应急助力的六星，同一干员只显示一次。开局前也可手动添加六星，所有后续随机先按参与范围筛选，再排除展板中的干员；可移除并在 6 秒内撤销。宽屏并排展示操作区与展板，窄屏可展开，手动添加入口始终可见。
- **随机词条挑战**：作为默认折叠的独立功能卡片，点击标题展开，折叠时保留已抽数量；并列展示“朝阳随机挑战-普通”“朝阳随机挑战-困难”“朝阳随机挑战-变态”和“仙术杯#9”四个词条池。支持多选，高亮表示参与，默认仅选中“朝阳随机挑战-普通”；每次从所选池合并去重后的未抽词条中等概率抽取1条，同一主题的已抽列表统一保留。以“禁用／仅限／要求”表达限制；三个朝阳词条池名称右上角均标注脚注1，仙术杯名称右上角标注脚注2，对应的[朝阳原始来源](https://www.bilibili.com/toy/MRFZ/index.html)与[仙术杯原始来源](https://live.bilibili.com/blackboard/era/5sWSFsRb4xZZ2hHC.html)链接按来源去重，紧凑排列在页脚分割线上方。
- **开局折叠**：确认后自动收起开局卡片，标题栏支持随时展开或收起，保留当前选择与随机结果。
- **完整开局随机**：一键生成分队、招募组合和每张招募券对应的干员。
- **希望硬约束**：全随机开局的全部干员总消耗不会超过本次开局的初始希望。
- **尽量选择高星**：全随机开局中，每个券位优先从当前希望可承担的最高星级中随机，不会固定高星出现在哪个券位。
- **规则适配**：支持后勤分队初始希望、战术分队招募减免、机械师自身减免，以及阿米娅多形态减免判定。
- **手选与局部随机**：分队和招募组合可以在弹窗中指定，也可以单独随机；已有阵容时更换其中一项会保留另一项并重新生成干员。还可重抽单个干员或重新随机整个开局。
- **自定义干员范围**：默认全部干员参与随机，后续新增干员自动选中，手动取消勾选的干员保持排除。按 6、5、4 星切换，各职业分组展示紧凑卡片，点击卡片切换参与状态，高亮表示已选；支持姓名搜索、职业筛选和仅看已选，提供“全选本星级”“清空本星级”快捷操作，三星固定参与。
- **设置本地保存**：干员范围以黑名单保存，仅记录手动排除的干员；抽取数量单独保存。下次访问自动恢复，并清理已失效的排除记录。

## 使用说明

1. 打开[在线页面](https://ark.slayerwalt.cn/)。首次访问会自动弹出使用说明，介绍随机范围、两种开局、局内招募和随机词条挑战；关闭后在当前浏览器记住，下次访问不再自动弹出。可随时点击页眉“说明”再次查看，支持关闭按钮、Escape 和点击遮罩关闭；浏览器存储不可用时仍可正常使用说明。
2. 点击“说明”右侧的“切换肉鸽”，通过缩略图选择肉鸽；目前可随机的主题为“沉沦者的黑流树海”。页面展示图保留肉鸽名称与编号，移除可用状态标签。
3. 默认使用全部干员。两种开局共用“干员随机范围设置”，随心所欲开局只使用其中的六星干员。需要自定义时，点击“干员随机范围”展板中的“调整范围”打开居中的设置弹窗，按星级和职业分组查找干员，点击卡片切换选中状态；高亮的干员参与随机。搜索和职业筛选只影响显示，“全选本星级”和“清空本星级”作用于当前星级的全部干员。
4. 点击“随机开局”卡片，在弹窗选择“随心所欲开局”或“全随机开局”，再点击“确认开局方式”。随心所欲按游戏实际给出的三张招募券填写职业，点击“抽取六星干员”，再选择一名并“确认开局”。重复职业可多次填写；点击已填券位，再选职业可直接替换，券位旁的叉号用于移除。分队提供“选择分队”和“随机分队”两个按钮；选择按钮打开弹窗，点击一项即可确定，随机后按钮变为“重新随机”。
5. 确认后可以“返回本轮结果”改选，仍显示本轮尚未进入“已选干员”的可选结果。“重新抽取干员”或“重新填写招募券”会清空本次选择；手动选择或随机分队保留可选结果和开局干员。
6. 选择“全随机开局”后，分队和招募组合均可先手动选择或独立随机。“开始随机”会沿用已选项目，随机补齐未选项目并生成干员。已有阵容后，选择或随机分队、组合会保留另一项并重新生成全部券位；点击干员头像或姓名重抽单个券位，“重新随机全部”会重新抽取分队、组合和干员。希望消耗由程序内部校验。要更换方式，点击“重置开局”，在弹窗中重新选择并确认；选择同一种方式也会清空开局草稿。
7. 随心所欲点击“确认开局”，全随机在所有券位都有干员后点击“确认开局”，所有实际确认的开局干员会进入本局名单，六星展示在“已选干员”，同时自动收起随机开局并将焦点移到局内操作。折叠标题下保留开局干员摘要，标题栏可随时展开或收起。重新确认其他开局会追加干员并清空局内可选结果，保留已有记录；重复确认同一结果不会重复添加。
8. 无需先随机或确认开局，可直接在“随机抽取干员”中点击实际获得的招募券，从“可选结果”中选择一名并“确认招募”。招募券以等宽卡片统一展示游戏原图和名称，不另设分类标题，任意券标为“任意”；更换时用高亮边框与勾选标记提示当前使用的券。干员选中状态显示在干员卡片上；“更换招募券”“重新抽取”“确认招募”和“放弃本次”集中在结果下方，确认招募使用主按钮样式，窄屏排列成两行。抽取与选中本身不登记；确认后加入本局名单并退出后续随机。可重新抽取、放弃本次，或通过“更换招募券”在操作区下方展开选择，点击新券抽取，替换当前可选结果。可选干员不足时按实际人数展示，不跨职业或星级补齐。
9. “已选干员”的“手动添加”用于登记游戏中的应急助力或自己想使用的六星，开局前就能使用，支持名称搜索和职业筛选，也可添加随机范围之外的六星。加入后立即从开局及局内可选结果中排除；全随机旧结果若包含刚添加的六星，需要重抽对应券位才能确认。点击展板内“移除”恢复其抽取资格，但仍受随机范围限制。手动添加与移除统一从“已选干员”操作，随机抽取干员区提供招募券选择、数量设置、抽取和确认操作。
10. “随机词条挑战”默认折叠，点击标题展开后，按来源和难度点击词条池切换参与状态，可同时选择多个池，高亮表示已选；默认仅选中“朝阳随机挑战-普通”池。点击“随机抽取词条”后，每次从所选池合并去重后的未抽词条中追加1条，最新词条排在最上方。取消全部池时暂停抽取。同一主题共用已抽列表，折叠卡片保留词条和选池，展开后恢复显示；调整选池不会清空或隐藏已抽词条；移除单条后恢复其抽取资格，“清空”移除当前主题的全部已抽词条。词条不自动更改干员随机范围，限制由玩家自行执行。

移除已选六星或挑战词条，以及清空挑战词条后，可以在 6 秒内撤销最近一次操作。恢复干员会同时恢复对应的随机排除状态。局内后续抽取、选择、手动添加、放弃、范围调整、确认新开局或切换主题会结束名单撤销；词条后续成功抽取或切换主题会结束词条撤销，调整所选词条池仍可撤销。

随心所欲开局只要求所填招募券对应的职业中有可用六星；四、五星范围为空不影响抽取。可选干员不足九名时使用实际人数，不跨职业或星级补齐；全部为空时提示核对招募券或调整范围。全随机开局要求 6、5、4 星范围均非空。

干员范围设置即时保存，仅影响后续随机，不会自动改掉本轮结果和已有阵容；已经抽出的可选结果仍可确认，但已招募的干员以及手动添加的六星会从可选结果中排除。选定的开局方式固定到下次重置；确认重置后，两种方式的开局草稿、分队、招募券和结果均清空，取消重置不改变任何选择。重抽或重置开局草稿不会修改本局名单，确认新开局后追加名单并清空局内可选结果，已有记录继续保留。切换到未开放主题再返回会恢复原主题的开局方式、草稿、本局名单、词条和折叠状态。词条记录独立于开局确认，重新确认开局不会清空词条；需要开始新一轮挑战时手动清空当前主题的已抽列表。刷新页面会清空开局方式、开局、本局名单和已抽词条，词条池恢复默认选择，手动排除记录和抽取数量设置仍保留；浏览器存储不可用时仍可在本次会话使用设置。

升级到黑名单存储时，旧版干员范围一次性重置为全选，包括旧“常见”名单、手动范围和清空状态；抽取数量等独立设置继续保留。之后只记录取消勾选的干员，后续数据更新自动选中新干员，已保存的排除项继续生效。“清空本星级”只排除当前已有干员，之后新增的干员仍会选中；“全选本星级”清除该星级的排除项。新版设置不会重复重置。

页面采用灰白背景与白色卡片，操作按钮和选中状态使用蓝色。随机开局、随机抽取干员和随机词条挑战在主操作区以独立卡片排列，肉鸽展示图下方提供“干员随机范围”展板与“调整范围”入口，按六星、五星、四星从左到右横向展示已选干员头像、首个头像对应的姓名和完整人数；窄屏也保持三栏，每个星级显示一张头像，较宽时显示更多，随范围设置即时更新。范围展板随页面滚动。宽屏优先分配空间给主操作区，“已选干员”在右侧保持可见；窄屏的展板可展开，可选结果按可用宽度排列，确认栏在区域内靠近屏幕底部并预留设备安全区。干员仅展示小头像与姓名，用高光边框表示星级：六星橙色、五星黄色、四星紫色、三星蓝色；悬停提示和读屏标签保留星级信息。点击干员后显示勾选角标，姓名加粗并加下划线，再单独确认；全随机开局结果直接点击干员重抽。抽取结果出现、名单新增及词条变化提供短促动效。设置与选择弹窗支持 Escape 关闭和键盘焦点恢复，所有动效尊重系统的减少动态效果设置。

## 随机规则

所有抽取先应用各星级的参与范围，再排除“已选干员”中的六星。随心所欲开局按游戏实际给出的三张招募券职业抽取，每张券配额为三名。同职业配额累加，同轮干员去重，缺额如实展示。玩家填写已经拿到的券，再从抽出的干员中确定一名六星开局干员，其余干员自行搭配。

全随机开局沿用以下希望规则：

- 黑流树海开局基础希望为 6；后勤分队额外提供 2 点初始希望。
- 初始招募中，六星、五星、四星及以下干员的基础消耗分别为 6、2、0。
- 首次开局采用预先选择或随机出的分队、招募组合，未选项目自动随机；随后打乱券位处理顺序。“重新随机全部”会重新抽取全部项目。
- 每个券位先应用参与范围并排除已选六星，再过滤职业、星级上限和剩余希望，从可承担的最高星级中随机一名干员；同次开局的六星不重复，单券位重抽也排除其他保留券位中的六星。
- 分队减免与干员自身减免可以叠加，最终希望消耗最低为 0。
- 更换分队或组合时会按当前分队的希望与减免、当前组合的券位限制重新随机全部券位；单独重摇券位时会保留其他券位已经消耗的希望。

“随机抽取干员”的所有招募券共用一组六星、五星总人数，默认六星5名、五星0名。点击“数量设置”可分别设置为0–99的整数，允许只抽某一星级，但合计至少1名；可恢复默认，保存后从下一次抽取生效，并在当前浏览器中记住。取消或关闭弹窗不修改设置，保存不改动当前结果、选择及名单。

招募券仅限定职业范围：单职业使用该职业；双职业、地面／高台及任意券在对应职业范围内合并抽取，不按职业倍增数量、不设每职业保底，任意券也按设置抽取五星。同轮按干员身份去重，阿米娅升变视为同一名干员，其他异格分别处理。当前数据中的阿米娅沿用医疗形态，仅参与医疗及包含医疗的招募券。抽取使用共享的五、六星参与名单，同时排除已招募干员和“已选干员”中的六星；人数不足时按实际人数展示，不跨星级或职业补齐，没有希望输入或费用校验。该数量设置只作用于“随机抽取干员”。

挑战词条按来源和难度分别维护，来源信息保留在数据中。“朝阳随机挑战-普通”池提供93条禁用词条，“朝阳随机挑战-困难”池提供55条仅限词条，“朝阳随机挑战-变态”池提供17条仅限词条。原站简单和普通共用同一词条范围，因此合为“朝阳随机挑战-普通”池；困难、变态各使用自己的词条范围，不累计其他难度池。本工具各池每次均抽取1条。

“仙术杯#9”提供5条限制，分别涉及 N15 难度、“板藤”处理、“命运所指”藏品提交、藏品主动选择和沙盘通关条件，保留各条的适用条件及例外。

抽取时将所选池的原分组展平并合并，限制类型和正文都相同的词条只保留一条；同文但限制类型不同的词条分别保留，跨池重复词条不会增加抽取权重。排除当前主题已抽词条后，对所有剩余词条等概率抽取，不按池、挑战难度或分组设置权重，也不自动筛选冲突。每个主题维护独立的已抽列表，调整所选池仅改变后续抽取范围；禁用、仅限和要求词条由玩家判断并执行。

## 游戏数据更新

结构化游戏数据来自 [yuanyan3060/ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)。网页不会在运行时请求该仓库；发生干员更新、黑流树海版本更新或相关规则调整后，再由维护者人工运行提取脚本：

```powershell
npm run extract -- <ArknightsGameResource 仓库路径>
```

生成的 `src/data/rogue-data.json` 会记录上游仓库、commit、游戏数据版本及输入文件 SHA-256。提取过程还会：

- 在业务数据没有变化时跳过写入，避免产生日期噪声。
- 输出干员、分队和招募组合的新增、移除及关键字段变化。
- 在数量下降时默认停止写入；确认属于正常版本变化后才能使用 `--allow-removals`。
- 检查干员数据与本地头像是否一一对应，缺图时保留纯文字降级能力。
