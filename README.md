## 项目简介

这个工具用于决定集成战略的开局。默认使用“候选开局”：玩家选择三个职业位，每位随机提供三名六星，再从本轮候选中确认一名起手干员，其余干员自行搭配。分队可以独立随机。

“一键随机”保留完整开局生成方式：随机选择分队和初始招募组合，再结合初始希望、分队减免和干员自身减免，为每张券随机一名当前预算能够招募的干员。

项目是纯静态网页，不需要登录，不连接游戏客户端，也没有后端服务。游戏数据和图片资源在构建时打包，浏览器只负责随机计算和保存本地设置。

## 功能亮点

- **六星候选开局**：三个职业位可以重复，最多提供九名不重复的六星候选，选中并确认一名起手干员；候选不足时展示实际人数和缺额。
- **两种模式独立**：切换候选开局和一键随机会保留各自的本次结果，返回候选可以继续改选。
- **完整开局随机**：一键生成分队、招募组合和每张招募券对应的干员。
- **希望硬约束**：一键随机的全部干员总消耗不会超过本次开局的初始希望。
- **尽量选择高星**：一键随机中，每个券位优先从当前希望可承担的最高星级中随机，不会固定高星出现在哪个券位。
- **规则适配**：支持后勤分队初始希望、战术分队招募减免、机械师自身减免，以及阿米娅多形态减免判定。
- **局部重摇**：可以单独重摇分队、招募组合或某一张招募券，也可以重新随机整个开局。
- **自定义干员范围**：默认全部干员参与随机。按 6、5、4 星切换，各职业分组展示紧凑卡片，点击卡片切换参与状态，高亮表示已选；支持姓名搜索、职业筛选和仅看已选，提供“全选”“清空”快捷操作，三星固定参与。
- **设置本地保存**：干员池设置保存在浏览器本地，下次访问会自动恢复，并清理数据更新后已经不存在的干员。

## 使用说明

1. 打开[在线页面](https://ark.slayerwalt.cn/)。
2. 点击“切换主题”，通过主题缩略图选择肉鸽主题；目前可随机的主题为“沉沦者的黑流树海”。
3. 默认使用全部干员。需要自定义时，点击“调整范围”打开设置抽屉，按星级和职业分组查找干员，点击卡片切换选中状态；高亮的干员参与随机。搜索和职业筛选只影响显示，“全选”和“清空”作用于当前星级的全部干员。
4. 默认进入“候选开局”。选择三个职业位，点击“抽取六星候选”，再选择一名并“确认起手”。同一职业可多次添加，点击已选职业位可以移除；分队可通过独立按钮随机。
5. 确认后可以“返回本轮候选”改选，候选保持不变。“重新抽取候选”或“重新选择职业”会清空本次选择；重抽分队保留候选和起手干员。
6. 切换到“一键随机”，点击“开始随机”生成完整开局。生成后可以重抽分队或组合，点击干员头像或姓名重抽单个券位，也可以点击“重新随机全部”。希望消耗由程序内部校验。

候选开局只要求所选职业中有可用六星；四、五星范围为空不影响抽取。候选不足九名时使用实际人数，不跨职业或星级补齐；全部为空时提示调整职业或范围。一键随机要求 6、5、4 星范围均非空。

设置即时保存，仅影响后续随机，不会自动改掉本轮候选和已有阵容；已经抽出的候选仍可确认。两种模式分别保留本次结果，切换到未开放主题再返回也会恢复原主题的开局。刷新页面会清空本次开局，参与名单仍保留；浏览器存储不可用时仍可在本次会话使用设置。

旧版保存的某星级范围若仍与原默认“常见”名单一致，会自动更新为该星级全选；手动修改过的范围和手动清空的设置继续保留。迁移后保存新版本标记，后续手动选择不会重复触发迁移。

页面采用居中限宽的浅色布局，干员仅展示小头像与姓名，用高光边框表示星级：六星橙色、五星黄色、四星紫色、三星蓝色；悬停提示和读屏标签保留星级信息。点击候选进行选择，已选姓名加粗并加下划线，再单独确认起手；一键随机结果直接点击干员重抽。使用说明可随时打开，面板支持 Escape 关闭和键盘焦点恢复，并尊重系统的减少动态效果设置。

## 随机规则

候选开局按用户的六星参与名单和三个职业位抽取，每个职业位配额为三名。同职业配额累加，同轮候选去重，缺额如实展示。这些职业位用于约束候选范围，不自动生成游戏内的招募组合；完成后仅确定一名六星起手，其余干员由玩家自行搭配。

一键随机沿用以下希望规则：

- 黑流树海开局基础希望为 6；后勤分队额外提供 2 点初始希望。
- 初始招募中，六星、五星、四星及以下干员的基础消耗分别为 6、2、0。
- 脚本先随机分队和招募组合，再打乱券位处理顺序。
- 每个券位会过滤职业、星级上限、用户干员池和剩余希望，然后从可承担的最高星级中随机一名干员。
- 分队减免与干员自身减免可以叠加，最终希望消耗最低为 0。
- 重摇分队时会按新的希望与减免重新随机全部券位；单独重摇券位时会保留其他券位已经消耗的希望。

## 本地开发

需要 Node.js `^20.19.0` 或 `>=22.12.0`，以及随 Node.js 提供的 npm。

```powershell
git clone https://github.com/slayerwalt/ArkRogueStartRandomizer.git
cd ArkRogueStartRandomizer
npm ci
npm run dev
```

常用命令：

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动本地开发服务器 |
| `npm run build` | 构建生产版本 |
| `npm run typecheck` | 运行 TypeScript 类型检查 |
| `npm test` | 运行 Vitest 测试 |
| `npm run extract -- <资源仓库路径>` | 从游戏资源仓库更新项目数据 |

## 游戏数据更新

结构化游戏数据来自 [yuanyan3060/ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)。网页不会在运行时请求该仓库；发生干员更新、黑流树海版本更新或相关规则调整后，再由维护者人工运行提取脚本：

```powershell
npm run extract -- <ArknightsGameResource 仓库路径>
```

生成的 `src/data/rogue-data.json` 会记录上游仓库、commit、游戏数据版本及输入文件 SHA-256。提取过程还会：

- 在业务数据没有变化时跳过写入，避免产生日期噪声。
- 输出干员、分队和招募组合的新增、移除及关键字段变化。
- 在数量下降时默认停止写入；确认属于正常版本变化后才能使用 `--allow-removals`。
- 检查干员数据与本地头像是否一一对应，缺图时保留纯文字降级能力。

## 项目结构

```text
src/components/       页面组件
src/composables/      随机会话与设置状态管理
src/lib/              随机规则、设置与数据校验
src/styles/           设计变量与组件样式
src/data/             构建时打包的游戏数据
src/assets/           主题、分队和干员图片
scripts/              游戏数据提取与更新检查
tests/                随机逻辑、会话协调和数据提取测试
```
