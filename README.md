## 项目简介

这个工具用于决定集成战略的开局。默认使用“随心所欲开局”：在游戏中选择“随心所欲”后，玩家按实际随机获得的三张招募券填写职业，工具为每张券随机提供三名六星，再由玩家从本轮候选中确认一名起手干员，其余干员自行搭配。分队可以手动选择或独立随机。

“全随机开局”可以直接随机分队、招募组合和全部开局干员，结合初始希望、分队减免和干员自身减免，为每张券随机一名当前预算能够招募的干员。

项目是纯静态网页，不需要登录，不连接游戏客户端，也没有后端服务。游戏数据和图片资源在构建时打包，浏览器只负责随机计算和保存本地设置。

## 功能亮点

- **随心所欲开局**：按游戏实际给出的三张券填写职业，重复职业可以多次填写，最多提供九名不重复的六星候选，选中并确认一名起手干员；候选不足时展示实际人数和缺额。
- **两种模式独立**：切换随心所欲开局和全随机开局会保留各自的本次结果，返回候选可以继续改选。
- **已招募干员**：确认开局后，在范围设置与开局卡片之间展示本次开局的六星干员，同一干员只显示一次；重新确认会更新名单。
- **开局折叠**：确认后自动收起开局卡片，标题栏支持随时展开或收起，保留当前选择与随机结果。
- **完整开局随机**：一键生成分队、招募组合和每张招募券对应的干员。
- **希望硬约束**：全随机开局的全部干员总消耗不会超过本次开局的初始希望。
- **尽量选择高星**：全随机开局中，每个券位优先从当前希望可承担的最高星级中随机，不会固定高星出现在哪个券位。
- **规则适配**：支持后勤分队初始希望、战术分队招募减免、机械师自身减免，以及阿米娅多形态减免判定。
- **手选与局部随机**：分队和招募组合可以在弹窗中指定，也可以单独随机；已有阵容时更换其中一项会保留另一项并重新生成干员。还可重抽单个干员或重新随机整个开局。
- **自定义干员范围**：默认全部干员参与随机。按 6、5、4 星切换，各职业分组展示紧凑卡片，点击卡片切换参与状态，高亮表示已选；支持姓名搜索、职业筛选和仅看已选，提供“全选”“清空”快捷操作，三星固定参与。
- **设置本地保存**：干员池设置保存在浏览器本地，下次访问会自动恢复，并清理数据更新后已经不存在的干员。

## 使用说明

1. 打开[在线页面](https://ark.slayerwalt.cn/)。
2. 点击“切换主题”，通过主题缩略图选择肉鸽主题；目前可随机的主题为“沉沦者的黑流树海”。
3. 默认使用全部干员。两种开局共用“干员随机范围设置”，随心所欲开局只使用其中的六星干员。需要自定义时，点击“调整范围”打开设置抽屉，按星级和职业分组查找干员，点击卡片切换选中状态；高亮的干员参与随机。搜索和职业筛选只影响显示，“全选”和“清空”作用于当前星级的全部干员。
4. 默认进入“随心所欲开局”。按游戏实际给出的三张招募券填写职业，点击“抽取六星候选”，再选择一名并“确认起手”。重复职业可多次填写，点击已填的券可以移除。分队提供“选择分队”和“随机分队”两个按钮；选择按钮打开弹窗，点击一项即可确定，随机后按钮变为“重新随机”。
5. 确认后可以“返回本轮候选”改选，候选保持不变。“重新抽取候选”或“重新填写招募券”会清空本次选择；手动选择或随机分队保留候选和起手干员。
6. 切换到“全随机开局”，分队和招募组合均可先手动选择或独立随机。“开始随机”会沿用已选项目，随机补齐未选项目并生成干员。已有阵容后，选择或随机分队、组合会保留另一项并重新生成全部券位；点击干员头像或姓名重抽单个券位，“重新随机全部”会重新抽取分队、组合和干员。希望消耗由程序内部校验。
7. 随心所欲点击“确认起手”，全随机在所有券位都有干员后点击“确认开局”，本次开局的六星干员会进入上方“已招募干员”卡片，同时自动收起随机开局。标题栏可随时展开或收起；重新确认会把名单更新为最新确认的开局，重复确认不会累加。完整开局没有六星时也可确认，名单会显示相应提示。

随心所欲开局只要求所填招募券对应的职业中有可用六星；四、五星范围为空不影响抽取。候选不足九名时使用实际人数，不跨职业或星级补齐；全部为空时提示核对招募券或调整范围。全随机开局要求 6、5、4 星范围均非空。

设置即时保存，仅影响后续随机，不会自动改掉本轮候选和已有阵容；已经抽出的候选仍可确认。两种模式分别保留本次结果，切换到未开放主题再返回也会恢复原主题的开局、已招募名单和折叠状态。已招募名单取自最近一次确认，调整范围、重抽或切换模式后，直到重新确认才更新。刷新页面会清空本次开局和已招募名单，参与名单仍保留；浏览器存储不可用时仍可在本次会话使用设置。

旧版保存的某星级范围若仍与原默认“常见”名单一致，会自动更新为该星级全选；手动修改过的范围和手动清空的设置继续保留。迁移后保存新版本标记，后续手动选择不会重复触发迁移。

页面采用居中限宽的浅色布局，干员仅展示小头像与姓名，用高光边框表示星级：六星橙色、五星黄色、四星紫色、三星蓝色；悬停提示和读屏标签保留星级信息。点击候选进行选择，已选姓名加粗并加下划线，再单独确认起手；全随机开局结果直接点击干员重抽。使用说明可随时打开，面板支持 Escape 关闭和键盘焦点恢复，并尊重系统的减少动态效果设置。

## 随机规则

随心所欲开局按游戏实际给出的三张招募券职业和用户的六星参与名单抽取，每张券配额为三名。同职业配额累加，同轮候选去重，缺额如实展示。玩家填写已经拿到的券，再从抽出的干员中确定一名六星起手，其余干员自行搭配。

全随机开局沿用以下希望规则：

- 黑流树海开局基础希望为 6；后勤分队额外提供 2 点初始希望。
- 初始招募中，六星、五星、四星及以下干员的基础消耗分别为 6、2、0。
- 首次开局采用预先选择或随机出的分队、招募组合，未选项目自动随机；随后打乱券位处理顺序。“重新随机全部”会重新抽取全部项目。
- 每个券位会过滤职业、星级上限、用户干员池和剩余希望，然后从可承担的最高星级中随机一名干员。
- 分队减免与干员自身减免可以叠加，最终希望消耗最低为 0。
- 更换分队或组合时会按当前分队的希望与减免、当前组合的券位限制重新随机全部券位；单独重摇券位时会保留其他券位已经消耗的希望。

## 本地开发

需要 Node.js `^20.19.0` 或 `>=22.12.0`，以及随 Node.js 提供的 npm。

```powershell
git clone https://github.com/slayerwalt/ArkRogueStartRandomizer.git
cd ArkRogueStartRandomizer
npm ci
npm run dev
```

常用命令：

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动本地开发服务器 |
| `npm run build` | 构建生产版本 |
| `npm run typecheck` | 运行 TypeScript 类型检查 |
| `npm test` | 运行 Vitest 测试 |
| `npm run extract -- <资源仓库路径>` | 从游戏资源仓库更新项目数据 |

## 游戏数据更新

结构化游戏数据来自 [yuanyan3060/ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)。网页不会在运行时请求该仓库；发生干员更新、黑流树海版本更新或相关规则调整后，再由维护者人工运行提取脚本：

```powershell
npm run extract -- <ArknightsGameResource 仓库路径>
```

生成的 `src/data/rogue-data.json` 会记录上游仓库、commit、游戏数据版本及输入文件 SHA-256。提取过程还会：

- 在业务数据没有变化时跳过写入，避免产生日期噪声。
- 输出干员、分队和招募组合的新增、移除及关键字段变化。
- 在数量下降时默认停止写入；确认属于正常版本变化后才能使用 `--allow-removals`。
- 检查干员数据与本地头像是否一一对应，缺图时保留纯文字降级能力。

