## 项目简介

这个工具用于决定集成战略的开局。进入“随机开局”时，先在弹窗中选择并确认一种开局方式。“随心所欲开局”对应游戏中的“随心所欲”：玩家按实际随机获得的三张招募券填写职业，工具为每张券随机提供三名六星，再由玩家从本轮候选中确认一名起手干员，其余干员自行搭配。分队可以手动选择或独立随机。

“全随机开局”可以直接随机分队、招募组合和全部开局干员，结合初始希望、分队减免和干员自身减免，为每张券随机一名当前预算能够招募的干员。

项目是纯静态网页，不需要登录，不连接游戏客户端，也没有后端服务。游戏数据和图片资源在构建时打包，浏览器只负责随机计算和保存本地设置。

## 功能亮点

- **随心所欲开局**：按游戏实际给出的三张券填写职业，重复职业可以多次填写，最多提供九名不重复的六星候选，选中并确认一名起手干员；候选不足时展示实际人数和缺额。
- **开局方式固定**：在弹窗中确认方式后，仅显示该方式的功能；通过“重置开局”重新选择，确认重置后清空开局草稿。取消弹窗保留当前开局。
- **局内随机干员**：支持单职业、双职业、地面／高台和任意招募券，抽取候选后由玩家确认一名；不输入或筛选希望。
- **本局名单**：确认开局后自动记录所有开局干员，局内招募、补录和临时招募继续追加；已招募和应急助力退出局内随机范围，应急助力可移除。
- **本局展板**：集中展示本局已招募的六星干员与挑战词条，同一干员只显示一次；其余星级可在局内名单管理中查看。宽屏并排展示操作区与展板，窄屏可展开本局概览。
- **随机词条**：当前收录 B站随机挑战生成器的161条词条。每次等概率抽取1条，可连续追加，同轮不重复；保留来源与“禁用／仅限”含义，不设置难度。
- **开局折叠**：确认后自动收起开局卡片，标题栏支持随时展开或收起，保留当前选择与随机结果。
- **完整开局随机**：一键生成分队、招募组合和每张招募券对应的干员。
- **希望硬约束**：全随机开局的全部干员总消耗不会超过本次开局的初始希望。
- **尽量选择高星**：全随机开局中，每个券位优先从当前希望可承担的最高星级中随机，不会固定高星出现在哪个券位。
- **规则适配**：支持后勤分队初始希望、战术分队招募减免、机械师自身减免，以及阿米娅多形态减免判定。
- **手选与局部随机**：分队和招募组合可以在弹窗中指定，也可以单独随机；已有阵容时更换其中一项会保留另一项并重新生成干员。还可重抽单个干员或重新随机整个开局。
- **自定义干员范围**：默认全部干员参与随机。按 6、5、4 星切换，各职业分组展示紧凑卡片，点击卡片切换参与状态，高亮表示已选；支持姓名搜索、职业筛选和仅看已选，提供“全选本星级”“清空本星级”快捷操作，三星固定参与。
- **设置本地保存**：干员池设置保存在浏览器本地，下次访问会自动恢复，并清理数据更新后已经不存在的干员。

## 使用说明

1. 打开[在线页面](https://ark.slayerwalt.cn/)。
2. 点击“切换主题”，通过主题缩略图选择肉鸽主题；目前可随机的主题为“沉沦者的黑流树海”。
3. 默认使用全部干员。两种开局共用“干员随机范围设置”，随心所欲开局只使用其中的六星干员。需要自定义时，点击工具栏的“随机范围”打开设置抽屉，按星级和职业分组查找干员，点击卡片切换选中状态；高亮的干员参与随机。搜索和职业筛选只影响显示，“全选本星级”和“清空本星级”作用于当前星级的全部干员。
4. 点击“随机开局”卡片，在弹窗选择“随心所欲开局”或“全随机开局”，再点击“确认开局方式”。随心所欲按游戏实际给出的三张招募券填写职业，点击“抽取六星候选”，再选择一名并“确认起手”。重复职业可多次填写；点击已填券位，再选职业可直接替换，券位旁的叉号用于移除。分队提供“选择分队”和“随机分队”两个按钮；选择按钮打开弹窗，点击一项即可确定，随机后按钮变为“重新随机”。
5. 确认后可以“返回本轮候选”改选，候选保持不变。“重新抽取候选”或“重新填写招募券”会清空本次选择；手动选择或随机分队保留候选和起手干员。
6. 选择“全随机开局”后，分队和招募组合均可先手动选择或独立随机。“开始随机”会沿用已选项目，随机补齐未选项目并生成干员。已有阵容后，选择或随机分队、组合会保留另一项并重新生成全部券位；点击干员头像或姓名重抽单个券位，“重新随机全部”会重新抽取分队、组合和干员。希望消耗由程序内部校验。要更换方式，点击“重置开局”，在弹窗中重新选择并确认；选择同一种方式也会清空开局草稿。
7. 随心所欲点击“确认起手”，全随机在所有券位都有干员后点击“确认开局”，所有实际确认的开局干员会进入本局名单，六星展示在本局展板，同时自动收起随机开局并将焦点移到局内操作。折叠标题下保留开局干员摘要，标题栏可随时展开或收起。重新确认其他开局会重置局内招募、候选和应急助力；重复确认同一结果不会重置本局。
8. 在“局内随机干员”中点击实际获得的券型，从候选中选择一名并“确认招募”。抽取与选中本身不登记；确认后加入本局名单并退出后续随机。可重新抽取、放弃本次，或通过“更换券型”直接选择新券抽取，替换当前候选。候选不足时按实际人数展示，不跨职业或星级补齐。
9. 自行搭配的开局干员可用“补录干员”登记；“临时招募”也加入已招募名单，两种登记会结束当前候选选择。“应急助力”只在登记期间排除，使用后可移除。名单管理可删除误录记录，删除后恢复随机资格。登记可选择随机范围之外的干员。
10. 在“随机词条”中选择词条池并点击“随机抽取词条”，每次追加1条，最新词条排在最上方。移除单条或清空后可再次抽到。不同池的抽取记录分开保存，切换池不会混合或清空；词条不按原站分组加权，不自动更改干员随机范围，限制由玩家自行执行。

移除招募记录、应急助力或挑战词条，以及清空挑战词条后，可以在 6 秒内撤销最近一次操作。恢复名单会同时恢复对应的局内排除状态。局内后续抽取、选择、登记、放弃、范围调整、确认新开局或切换主题会结束名单撤销；词条后续抽取、切换词条池或主题会结束词条撤销。

随心所欲开局只要求所填招募券对应的职业中有可用六星；四、五星范围为空不影响抽取。候选不足九名时使用实际人数，不跨职业或星级补齐；全部为空时提示核对招募券或调整范围。全随机开局要求 6、5、4 星范围均非空。

设置即时保存，仅影响后续随机，不会自动改掉本轮候选和已有阵容；已经抽出的候选仍可确认，但已登记为招募或应急助力的候选会被排除。选定的开局方式固定到下次重置；确认重置后，两种方式的开局草稿、分队、招募券和结果均清空，取消重置不改变任何选择。重抽或重置开局草稿不会修改本局名单，确认新开局后才替换本局招募、候选与应急助力。切换到未开放主题再返回会恢复原主题的开局方式、草稿、本局名单、词条和折叠状态。词条记录独立于开局确认，重新确认开局不会清空词条；需要开始新一轮挑战时手动清空当前池。刷新页面会清空开局方式、开局、本局名单和已抽词条，参与名单仍保留；浏览器存储不可用时仍可在本次会话使用设置。

旧版保存的某星级范围若仍与原默认“常见”名单一致，会自动更新为该星级全选；手动修改过的范围和手动清空的设置继续保留。迁移后保存新版本标记，后续手动选择不会重复触发迁移。

页面采用灰白背景与白色卡片，操作按钮和选中状态使用蓝色。宽屏并排显示操作区和本局展板，展板在滚动时保持可见；窄屏的展板可展开，候选确认栏在区域内靠近屏幕底部。干员仅展示小头像与姓名，用高光边框表示星级：六星橙色、五星黄色、四星紫色、三星蓝色；悬停提示和读屏标签保留星级信息。点击候选后显示勾选角标，姓名加粗并加下划线，再单独确认；全随机开局结果直接点击干员重抽。候选出现、展板新增及词条变化提供短促动效。设置与选择弹窗支持 Escape 关闭和键盘焦点恢复，所有动效尊重系统的减少动态效果设置。

## 随机规则

随心所欲开局按游戏实际给出的三张招募券职业和用户的六星参与名单抽取，每张券配额为三名。同职业配额累加，同轮候选去重，缺额如实展示。玩家填写已经拿到的券，再从抽出的干员中确定一名六星起手，其余干员自行搭配。

全随机开局沿用以下希望规则：

- 黑流树海开局基础希望为 6；后勤分队额外提供 2 点初始希望。
- 初始招募中，六星、五星、四星及以下干员的基础消耗分别为 6、2、0。
- 首次开局采用预先选择或随机出的分队、招募组合，未选项目自动随机；随后打乱券位处理顺序。“重新随机全部”会重新抽取全部项目。
- 每个券位会过滤职业、星级上限、用户干员池和剩余希望，然后从可承担的最高星级中随机一名干员。
- 分队减免与干员自身减免可以叠加，最终希望消耗最低为 0。
- 更换分队或组合时会按当前分队的希望与减免、当前组合的券位限制重新随机全部券位；单独重摇券位时会保留其他券位已经消耗的希望。

局内抽取沿用参考抽取器1.2普通档的固定配额，不提供难度选择：单职业券为2名六星和3名五星；双职业券每职业各2名六星和3名五星；地面／高台券在对应四职业中合并抽取6名六星和8名五星，不设每职业保底；任意券为16名六星。同轮按干员身份去重，阿米娅升变视为同一名干员，其他异格分别处理。当前数据中的阿米娅沿用医疗形态，仅参与医疗及包含医疗的券型。局内抽取使用共享的五、六星参与名单，同时排除开局、局内、补录、临时招募及应急助力干员；没有希望输入或费用校验。

挑战词条按来源分别维护。当前 B站池保留原始词条和限制类型，将原分组展平后对所有未抽词条等概率抽取，不使用难度、分组权重或自动冲突筛选。仅限和禁用词条可能同时出现，由玩家判断如何执行；每个主题下的每个池独立去重。

## 本地开发

需要 Node.js `^20.19.0` 或 `>=22.12.0`，以及随 Node.js 提供的 npm。

```powershell
git clone https://github.com/slayerwalt/ArkRogueStartRandomizer.git
cd ArkRogueStartRandomizer
npm ci
npm run dev
```

常用命令：

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动本地开发服务器 |
| `npm run build` | 构建生产版本 |
| `npm run typecheck` | 运行 TypeScript 类型检查 |
| `npm test` | 运行 Vitest 测试 |
| `npm run extract -- <资源仓库路径>` | 从游戏资源仓库更新项目数据 |

## 游戏数据更新

结构化游戏数据来自 [yuanyan3060/ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)。网页不会在运行时请求该仓库；发生干员更新、黑流树海版本更新或相关规则调整后，再由维护者人工运行提取脚本：

```powershell
npm run extract -- <ArknightsGameResource 仓库路径>
```

生成的 `src/data/rogue-data.json` 会记录上游仓库、commit、游戏数据版本及输入文件 SHA-256。提取过程还会：

- 在业务数据没有变化时跳过写入，避免产生日期噪声。
- 输出干员、分队和招募组合的新增、移除及关键字段变化。
- 在数量下降时默认停止写入；确认属于正常版本变化后才能使用 `--allow-removals`。
- 检查干员数据与本地头像是否一一对应，缺图时保留纯文字降级能力。
